# STANCE CRIME — Racing Engine
## Техническое задание на выделение движка из сцены поездки

Статус: проект архитектуры. Базовая сцена: v28.13, коммит 965c31a44f1a7037c3bcc7f5d67102429fb1fc2b. Реструктуризация ресурсов: v28.14. Не считать описанные ниже новые системы реализованными.

## 1. Цель и ограничения

Создать переиспользуемый Canvas 2D движок псевдо-3D гонки на основе текущей поездки. Существующая сцена остаётся песочницей для настройки и проверки ресурсов. Новый режим игры использует то же ядро, без дублирования физики и графики. Набережная, общая библиотека спрайтов и BEETLE BRAWL не изменяются. Первоначально — одиночный бесконечный заезд; круговые гонки, сетевой режим и противники с AI не входят в MVP.

## 2. Зафиксированное состояние текущей сцены

| Система | Текущая реализация |
|---|---|
| Canvas | 864 × 432, горизонт y=183, depth=1800, FOG_DEPTH=9600 |
| Проекция | q=1/(1+z/155), y=183+249*q, half=600*q; плавное смещение центра от distance и z |
| Координаты | z — продольная дистанция впереди камеры, lane — нормализованная поперечная координата; меньший z ближе |
| Полосы | 4, центры -0.75/-0.25/+0.25/+0.75; два направления в режиме two |
| Игрок | m412-01 по умолчанию, VAZ как эталон размеров; PLAYER-PERSPECTIVE.md обязателен |
| Скорость | физическая 0–180, отображение 0–140 км/ч; газ +32/с, тормоз -65/с, без газа скорость сохраняется |
| Дистанция | distance += velocity*3*dt; это условные единицы, не метры |
| Транспорт | DriveTraffic.create / createPassing; попутный въезжает снизу, встречный с горизонта |
| Урон | 5 сердечек, боковой удар 0.5, встречный 1; остановка при 0 |
| Окружение | поля, заборы, ЛЭП, лошади 1%, техника 12%, стада 6% на независимый слот свободного луга, вне посевов |
| Буферы | трактор—лошадь 400, КамАЗ—лошадь 1800, техника—граница поля 300, техника—стадо 400 от продольного диапазона стада; стадо—поле 100 на той же стороне |
| Отрисовка | общая очередь по z от дальнего к ближнему, priority для равной глубины; тени и эффекты |
| Оптимизация | кеш фона, 16 уровней тумана, кеш размещения техники и стад, отсечение невидимого |
| Ввод | клавиатура и независимые мобильные pointer-зоны, пауза, настройки |

Изменение этих значений — только через явно заданную конфигурацию. Не возвращать старое масштабирование M412 по независимым ракурсам. Не заменять перспективу обгона обычной проекцией отрицательного z: у неё есть полюс при z=-155. 

## 3. Предлагаемая структура ядра

```text
scene-preview/
  scene-preview-drive.html          # существующая песочница
  racing-preview.html               # будущий игровой адаптер
  engine/
    config.js                       # значения по умолчанию, схема настроек
    clock.js                        # фиксированный шаг симуляции
    state.js                        # состояние сессии
    projection.js                   # project, passingProjection, lane helpers
    input.js                        # нормализованный ввод
    player.js                       # движение, повороты, габариты
    traffic.js                      # адаптация DriveTraffic
    world.js                        # детерминированное окружение
    obstacles.js                    # будущие препятствия
```

Это целевая структура, не текущий список файлов. При первом выделении сохранить существующие модули через адаптеры, затем переносить их по одному. Не создавать второй независимый цикл requestAnimationFrame для одной сцены. Общие ресурсы брать из ../sprites/catalog.js; графику окружения из assets/webp/drive/. URL разрешать относительно модуля/явно переданного baseURL; не полагаться на текущий URL HTML.

## 4. Контракты данных

```js
// Предлагаемые контракты, не готовый API.
const config = {
  mode: 'preview', seed: 12345,
  fixedDt: 1/60, maxSteps: 5,
  player: { maxHealth: 5, maxVelocity: 180, acceleration: 32, braking: 65 },
  traffic: { ratio: 130, mode: 'one' },
  obstacles: { enabled: false, minGap: 400 },
  scoring: { enabled: false, distanceFactor: 0.1, overtakeBonus: 25 },
};
const state = {
  phase: 'ready', elapsed: 0, distance: 0, score: 0,
  player: { x: 0, velocity: 0, health: 5 },
  entities: [],
};
const entity = {
  id: 'unique-id', kind: 'traffic', worldZ: 0, lane: 0,
  relativeVelocity: 0, collider: { halfWidth: 0.1, halfDepth: 20 },
  active: true, hit: false, sprite: 'asset-key'
};
```

Хранить мировые координаты либо относительный z с явным указанием системы; при переходе использовать z = worldZ - state.distance. Не сравнивать экранные пиксели с мировыми единицами. События: collision, damage, overtake, obstaclePassed, pickup, gameOver. Каждое событие содержит entityId, sessionId, simulationTick и данные; очки/урон применяются один раз. Рендерер не изменяет игровое состояние.

## 5. Цикл и жизненный цикл

```text
requestAnimationFrame
  -> sample input
  -> accumulator += clamped wall delta
  -> fixed update (1/60 s, максимум 5 шагов)
       player -> distance -> world/traffic -> obstacles
       -> collision events -> damage -> score -> difficulty -> phase
  -> interpolate render state
  -> draw ground -> build depth queue -> sort -> draw -> HUD
```

При перегрузке ограничить накопитель, не пытаться бесконечно догонять время. Пауза и скрытая вкладка прекращают симуляцию; при возвращении сбросить временную отметку. В gameOver не начислять очки и не создавать новые объекты. Restart очищает сущности, таймеры, очки, столкновения, ввод и эффекты, восстанавливает 5 HP; кеши текстур можно сохранить. Dispose снимает слушатели и отменяет RAF. HUD обновлять при изменениях значений. Отдельно проверить, что переключение настроек в preview не ломает ввод.

## 6. Генерация препятствий (следующий этап)

Начать с неподвижных дорожных объектов: конус, барьер, яма; добавить движущиеся только после тестирования. Каждый объект имеет тип, спрайт, полосу, мировую координату, размеры коллайдера, урон и состояние прохождения. Декорации обочины никогда не становятся препятствиями автоматически.

- Генерация по seed и мировым слотам, не по случайному числу на каждом кадре.
- Первые препятствия после стартового безопасного участка; пример настройки 600 единиц.
- Спавн впереди видимой зоны столкновения, с достаточным временем реакции; например не менее 2.0 с при максимальной скорости. Дистанцию считать через velocity*3, а не км/ч из HUD.
- Минимальный зазор 400 единиц — начальный предложенный параметр, регулируемый после тестов.
- Проверять занятость полос транспортом и препятствиями на прогнозируемом интервале, оставлять минимум один реально достижимый безопасный путь. Учитывать время перестроения и текущую скорость.
- Не генерировать препятствия в задней зоне игрока и не телепортировать активные объекты.
- Удалять только после прохождения камеры; использовать ограниченный пул объектов.
- Неподвижное препятствие приближается с движением мира; у движущегося отдельная скорость.

## 7. Столкновения

Вынести проверку из HTML в collision.js. Использовать swept-проверку по продольному интервалу между предыдущим и текущим шагом и поперечное пересечение габаритов. Учитывать фактический масштаб игрока и автомобиля, без привязки только к номеру полосы. Сохранять действующую логику бокового удара и защиты занятой полосы при новом обгоне; активный обгоняющий автомобиль не исчезает при перестроении.

| Событие | Урон | Статус |
|---|---:|---|
| Встречный удар | 1 | существующее правило |
| Боковой удар | 0.5 | существующее правило |
| Конус | 0.5 | предложение |
| Барьер | 1 | предложение |
| Яма | 0.5 | предложение |

Одна потеря HP на один контакт/объект; эффект отталкивания, вспышка и частицы через события. Не вводить случайный урон без столкновения. Половинки сердечек сохраняются. Проверить быстрые пересечения, остановку, повторный контакт, два одновременных события и нулевую прочность.

## 8. Счётчик и игровой HUD

MVP: расстояние, очки, прочность, скорость, лучший результат. Начальное предложение: floor(distance*0.1) очков за пройденный путь и +25 за успешный обгон игроком или безопасное прохождение препятствия (разные события и настраиваемые бонусы). Считать только успешные действия: автомобиль, обогнавший игрока сзади, сам по себе бонус не даёт. Уникальный ID исключает повторное начисление. Не считать условную дистанцию километрами до утверждения коэффициента перевода. Пауза не увеличивает счёт. Лучший результат хранить в localStorage с версией схемы, безопасно обрабатывать отсутствие доступа; сетевой рейтинг — отдельный этап. Экран результата: очки, дистанция, причина завершения, повторить заезд, выход.

## 9. Сложность

Не менять скорость симуляции для повышения сложности. Увеличивать интенсивность препятствий и разнообразие паттернов плавно, по дистанции или времени сессии, с ограничением верхнего уровня. Предложение: 3 уровня, переходы после 3000 и 7000 условных единиц; интервалы и бонусы вынести в конфиг. Каждый паттерн проходит проверку безопасного пути. Не менять существующие шансы декораций как часть сложности.

## 10. Рендеринг и производительность

Порядок: фон и поверхность -> очередь всех вертикальных объектов (включая препятствия, транспорт, игрока) -> экранные эффекты -> HUD. Сортировка по глубине, а не типу; один спрайт стада. Тени привязаны к объекту. Сохранить кеш тумана и фон; не менять размеры вспомогательного Canvas на каждый объект/кадр. Не выделять новые большие буферы внутри цикла. Ограничить кеши и пулы, отсекать объекты до сортировки. Не загружать PNG/SVG исходники в рантайме. Использовать nearest-neighbor и базовое разрешение 864×432. Адаптация качества только визуальная: уменьшать мелкое зерно, число сегментов проводов/заборов, частицы; не менять физику, препятствия и коллайдеры. Цели тестов: стабильные 60 FPS на целевом ПК, не ниже 30 FPS на выбранном мобильном устройстве; измерить p50/p95 времени кадра, отдельно update и render, длительность 60 с после прогрева. Это цели, не измеренные результаты.

## 11. Этапы реализации и критерии готовности

1. **Выделение ядра:** перенести projection, player, clock и renderer; оба режима используют один код; визуальный и поведенческий паритет с preview.
2. **Сессия:** состояния ready/running/paused/gameOver, restart/dispose, воспроизводимый seed; тесты паузы и повторного старта.
3. **Препятствия и коллизии:** типы объектов, генерация, безопасные маршруты, урон; тесты высокой скорости и перестроения.
4. **Счёт и HUD:** события прохождения, итог, рекорд; тесты начисления ровно один раз и отсутствия начислений на паузе.
5. **Баланс и производительность:** сложность, мобильное управление, профили качества; измерения FPS и памяти на реальных устройствах.
6. **Интеграция:** отдельная страница гоночной игры, ссылка из меню STANCE CRIME только после проверки; Sprite Lab остаётся источником ресурсов и тестовой площадкой.

## 12. Обязательные регрессионные тесты

- Обгон начинается снизу на свободной полосе; занятая полоса не получает новый обгон; боковой контакт не удаляет машину.
- 5 -> 4.5 -> 3.5 HP при боковом и встречном ударе; правильная половина сердца; 0 останавливает игру.
- Ракурсы M412/VAZ, неподвижное руление, ускорение/тормоз и мобильные pointer-события соответствуют PLAYER-PERSPECTIVE.md.
- Ближний объект перекрывает дальний независимо от типа; туман не просвечивает силуэт.
- Буферы 400/1800/300/400/100 проверяются по мировым координатам, в том числе за пределами видимого окна.
- Детерминированный генератор не меняет уже созданные объекты при переключении видимости.
- Нет ошибок загрузки WebP, отсутствующих URL, повторных RAF или роста кеша при долгой поездке.
- Проверка Chrome/Firefox/Safari и iPhone/Android: управление, пауза, изменение размеров окна, повторный старт.

## 13. Инструкция для следующей итерации разработки

Сначала прочитать этот файл, README и PLAYER-PERSPECTIVE.md, затем актуальный код. Реализовать этап 1 отдельным небольшим коммитом, не добавляя одновременно препятствия, счёт и новую графику. Снять базовые показатели и сравнить после переноса. Следующие этапы включать флагами config, по умолчанию отключёнными в песочнице. Новые значения баланса выше являются предложениями до подтверждения владельцем проекта. При изменениях фиксировать коммит, версию кеша, результаты тестов и непроверенные ограничения.
